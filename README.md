# FAIRY AI / Purple Hub

**Нативный Android-проект на Kotlin и Jetpack Compose.** Purple Hub объединяет FAIRY AI, локальные инструменты, ZZZ Companion и Password Vault в одном приложении.

> **Статус:** исходный код версии 5.6.3. Это любительский open-source проект. Он не является официальным приложением OpenAI, Google, HoYoverse или других упомянутых сервисов.

## Возможности

### FAIRY AI
- Нативный чат на Jetpack Compose с поддержкой Chat Completions API у совместимых провайдеров.
- Настраиваемые Base URL, model ID и собственный API-ключ.
- Голосовой ввод средствами Android Speech Recognizer и озвучивание через Android Text-to-Speech.
- Локальные заметки и отдельная память. Передача памяти в контекст управляется настройкой приватности.
- API Monitor: журнал последних вызовов, ошибки, HTTP 429, задержка и usage-токены, если провайдер возвращает их.
- Отдельный режим веб-поиска через OpenAI Responses API с `web_search` (требует совместимые API-модель и аккаунт).

### Файлы и изображения
- Вложения из галереи, камеры и документы.
- Локальное извлечение текста из поддерживаемых документов; PDF обрабатывается в пределах первых страниц, указанных в интерфейсе/документации.
- ML Kit используется для локального OCR и базовой классификации изображений.
- Для смыслового анализа изображения FAIRY Vision отправляет сжатую копию выбранному AI-провайдеру **только после отдельного подтверждения пользователя**. Нужна vision-capable модель, поддерживающая формат запроса приложения.

### Остальные модули
- **ZZZ Companion:** локальный учёт круток, pity, гаранта, баннеров, отряда и материалов. Приложение не подключается к аккаунту HoYoverse и не читает данные игры.
- **Password Vault:** генератор и локальное зашифрованное хранилище записей.
- **Control Center:** голос, память, API Monitor, приватность, уведомления и резервные копии.
- **Аккаунт:** необязательная Firebase Authentication. Вход сам по себе не включает синхронизацию личных данных.

## Приватность и безопасность

- История, заметки, память, напоминания и данные модулей хранятся локально на устройстве.
- AI-запросы отправляются выбранному пользователем API-провайдеру. Его тарифы, лимиты, правила хранения и обработки данных применяются к таким запросам.
- Локальная обработка OCR/документов не требует отдельного платного AI API. Смысловой vision-анализ и обычный AI-чат используют выбранный API и могут расходовать его лимит.
- API-ключ приложения хранится с использованием Android Keystore.
- Password Vault использует AES-GCM и PBKDF2-HMAC-SHA256 для защиты хранимых записей.
- Экспорт FAIRY в JSON **не зашифрован**. Не публикуйте резервные копии, API-ключи, пароли, `google-services.json`, keystore-файлы или личные данные.
- Firebase конфигурация индивидуальна: `app/google-services.json` не включён в репозиторий. Без него проект должен запускаться в локальном режиме.

Ни один клиентский механизм шифрования не защищает данные от всех возможных угроз. Не используйте приложение как единственное место хранения критически важных секретов.

## Сборка

### Требования
- JDK 17
- Android SDK Platform 35
- Android Gradle Plugin 8.7.3
- Gradle 8.9 или совместимая версия
- Kotlin / Compose Compiler Plugin 2.4.21 (версии указаны в `build.gradle`)

### Шаги
1. Клонируйте репозиторий или скачайте ZIP исходников.
2. Откройте корневую папку проекта как Gradle-проект в Android Studio либо совместимой Android IDE.
3. Установите Android SDK Platform 35 и дождитесь Gradle Sync.
4. Соберите `:app:assembleDebug` или используйте **Build APK(s)** в IDE.
5. Debug APK обычно появляется в `app/build/outputs/apk/debug/app-debug.apk`.

Проект не содержит `google-services.json`, signing keystore или готового APK. Firebase — необязательная настройка; см. [инструкции по Firebase](docs/FIREBASE_SETUP_RU.md). Для публикации своего APK подпишите его собственным ключом и не добавляйте приватный keystore в Git.

### Примечание о Gradle Wrapper

В исходном архиве 5.6.3 нет `gradlew` и `gradle-wrapper.jar`. Откройте проект в Android IDE с установленным Gradle либо добавьте стандартный Gradle Wrapper из своей среды разработки.

## Релизы и APK

- Исходный код находится в основной ветке репозитория.
- Готовые APK публикуются отдельно в разделе **Releases → Assets**.
- GitHub автоматически генерирует для каждого релиза архивы **Source code (zip)** и **Source code (tar.gz)**. Это два формата одного и того же снимка исходного кода, а не два разных APK и не два отдельных проекта.
- Перед установкой APK проверяйте тег версии и автора релиза. APK, подписанный другим ключом, не сможет обновить вашу установленную сборку поверх неё.
